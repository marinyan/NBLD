# NBLD配置更新（2026-09-09）

パッケージ C500H→C800H、第2段 F100H→F800H、スタック上端 F400H→FB00H。
bootstrapはF000H、一時第2段はC8C0Hのまま。BASIC作業用640バイトも維持する。
第2段631バイト、スタックまで137バイト。ビルド検査で最低64バイトを確保する。
既定では実行中の第2段とスタック（F800H〜FAFFH）への上書きを拒否する。
明示オプションでの最終コピーは[ローダー領域の最終上書き](finalizer-ja.md)を参照。
NBLD v3形式・LZSS・作品固有セグメントは変更しない。

読み込み中は画面RAMの一部を使用する。第2段はDI後にROMを呼ばず動作し、
作品へ移ってから各作品がスタックと表示を初期化する。
画面RAMへのロード中の表示は完成したゲーム画面ではない。

| 上限／余白 | 前 | 後 |
|---|---:|---:|
| BASIC全体の上限（バイト） | 16,991 | 17,759 |
| パッケージ領域の上限 | 11,264 | 12,288 |
| BASICサイズ制約込みのパッケージ最大長※ | 11,127 | 11,688 |
| 検証ケースAのBASIC余白 | 412 | 1,180 |
| 検証ケースAのパッケージ余白 | 440 | 1,464 |

※現行631バイト第2段・240文字REM行の生成規則での値。
768バイトのBASIC追加容量は、Base64等の費用を除くとパッケージ561バイトに相当する。
ゲーム常駐RAMや、同じペイロードのテープサイズが減る変更ではない。

## 検証

- tests/capacity.ps1: 決定的なデータで上限を探索。BASIC 17,759バイトちょうど、
  パッケージ11,688バイト、展開10,357バイト。入力が1バイト増えた場合は拒否。
- tests/capacity-boot.ps1: 上限テープをCLOAD→RUNし、BASIC全17,759バイトと
  展開全10,357バイトが一致。BASIC作業用640バイトを残した限界まで検証。
- 検証ケースA: CLOAD→RUN、コード13,228バイト、BIN直接起動との画面一致。
- 検証ケースB（3構成）: 各既存テストでCLOAD・タイトル・ゲーム開始PASS。
  ROM裏RAMを使う構成での資産の検証もPASS。
- 検証ケースC: CLOAD→RUN、0000HのROM裏RAMと8000Hの通常RAM、タイトル動作PASS。
- 検証ケースD: CLOAD→RUN、セグメント・タイトル動作PASS。
- 全利用先の共通ソース2本は正本と同一。SjASMPlusとz80asmの第2段も同一。
  第2段SHA-256: 02df5a4134b83c8bdc329291cfd9b238c8022acd677c0febe4da67daf27e4afd。

修正版M88VのN802で機能を検証した。実機での検証と速度評価は行っていない。
既存テストに表示されるFPSは性能判断には用いない。

ゲーム3作品の同梱コピーは今回も正本から同期している。コピーを廃止して
参照依存へ移行する作業は未実施。既存の方針文書の未コミット変更はそのまま保護した。

## 起動テストの再実行

`tests/capacity.ps1 -AssemblerPath 'C:\path\to\sjasmplus.exe'` で上限テープを生成後、
接続中のM88Vに対して次を実行する。テストはエミュレーターをリセットする。

```powershell
./tests/capacity-boot.ps1 `
    -ConnectionFile 'C:\path\to\connection.json' `
    -M88V 'C:\path\to\M88V'
```

`-M88V` は `scripts/m88ctl.ps1` と `scripts/type_nbasic.ps1` を含むディレクトリ。
省略時は、このリポジトリと同じ親ディレクトリにある `M88V` を使う。
